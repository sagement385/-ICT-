# 충북 응급환자 병원 지원 정책 초안

상태: `DRAFT` · `enabled=false` · 의료진·119 구급상황관리센터 검토 전

이 문서는 병원 추천을 자동으로 결정하는 의료 지침이 아니다. 응급의료종사자와 의료지도의사의 판단을 보조하기 위한 데이터 처리·검증 정책의 초안이다. 승인 전에는 DB에 활성 정책으로 등록하지 않는다.

## 1. 근거와 역할 경계

- 병원 전 중증도 입력은 교육받은 응급의료종사자가 수행한 Pre-KTAS 또는 기관이 승인한 분류 결과를 입력으로 받는다.
- 자유 텍스트 증상, 의식·호흡·출혈 문장만으로 시스템이 KTAS/Pre-KTAS 등급을 추론하지 않는다.
- 응급의료기관의 역할과 지정 기준은 응급의료법 및 시행규칙의 현행 기준을 참조한다.
- 시스템은 이송 명령, 수용 확정, 진단, 치료 우선순위를 결정하지 않는다.

## 2. 후보 병원 처리 규칙

다음은 임상 판단이 아닌 데이터 품질·운영 안전 규칙이다.

1. 환자 좌표가 없으면 주변 병원과 실제 경로를 조회하지 않는다.
2. 병원 좌표가 없으면 거리·경로 계산 후보에서 제외한다.
3. 기본 후보 반경은 10km이며 API 입력은 5~10km로 제한한다.
4. 병원 수용 가능 여부가 없거나 오래된 경우 “수용 가능”으로 간주하지 않는다. 결과에 경고를 붙이고 구급대원 또는 병원 확인을 요구한다.
5. 실제 경로가 없으면 이동시간 기반 순위를 생성하지 않는다.
6. 진료과목·전문의·특수진료·장비는 확인된 원본 필드가 있을 때만 특징값으로 사용한다. 필드 의미가 확인되지 않은 값은 결측으로 유지한다.
7. 동일 병원의 여러 출처가 충돌하면 자동으로 우선순위를 정하지 않고 충돌 경고를 남긴다.

## 3. 환자 중증도 처리

현재 입력 계약의 `urgency_level`은 “외부에서 확인된 분류 결과”를 보존하는 필드로만 사용한다.

- `Pre-KTAS 1~5`의 세부 판정 로직을 이 프로젝트 코드에 재작성하지 않는다.
- 분류 결과가 없거나 출처가 불명확하면 중증도 기반 병원 제외·우선순위를 적용하지 않는다.
- 중증도에 따른 기관 유형 매핑은 충북 지역 응급의료협의체와 의료지도의사의 승인 문서가 확보된 뒤 별도 정책 버전으로 추가한다.

## 4. 점수 요소 초안

아래 요소는 구현 후보이며 가중치는 비워 둔다. 숫자 가중치는 의료·운영 검토와 검증 데이터 승인 없이는 입력하지 않는다.

| 요소 | 원본 | 사용 조건 | 현재 상태 |
| --- | --- | --- | --- |
| 실제 이동시간 | Naver Directions | 요청 시각·경로 응답이 유효함 | 후보 |
| 진료과목 일치 | HIRA 상세정보 | 환자 요구 진료과목과 매핑표 승인 필요 | 후보 |
| 전문의·특수진료 역량 | HIRA 상세정보 | 필드 의미와 최신성 검증 필요 | 후보 |
| 수용 상태 | NEMC | `hv*` 코드 의미와 병원 확인 절차 필요 | 보류 |
| 데이터 최신성 | 각 출처의 `fetched_at` | 만료 기준 승인 필요 | 후보 |

거리와 이동시간은 상관될 수 있으므로 두 요소를 동시에 사용할 때 중복 반영 여부를 검토한다.

## 5. 활성화 조건

정책을 `enabled=true`로 변경하기 전에 다음을 충족해야 한다.

- 응급의학 전문의 또는 의료지도의사 검토자와 검토일 기록
- 충북 119·응급의료기관의 수용 확인 절차 승인
- Pre-KTAS 입력의 출처·등급·누락 처리 합의
- 각 데이터 필드의 의미·갱신주기·stale 기준 승인
- 과거 사례 또는 별도 검증 세트에 대한 오탐·누락 평가
- 가중치 합의 및 버전 고정
- 실패 시 사람이 확인할 화면·경고·감사로그 확인

## 6. 등록 절차

현재 초안은 DB에 쓰지 않고 구조만 검증한다.

```powershell
cd backend
python scripts/create_policy.py --file ..\docs\recommendation-policy-draft.json --validate-only
```

의료·운영 검토가 끝난 승인 문서만 `approval_status=APPROVED`와 숫자 가중치를 포함해 별도 파일로 만든다. 승인 문서는 기본적으로 비활성 상태로 등록하고, 실제 활성화는 명시적으로 수행한다.

```powershell
python scripts/create_policy.py --file ..\docs\recommendation-policy-approved.json --insert
python scripts/create_policy.py --file ..\docs\recommendation-policy-approved.json --insert --activate
```

승인 전 초안이나 가중치가 비어 있는 문서는 importer가 DB 등록을 거부한다.
